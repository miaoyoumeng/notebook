##  运维策略
1、保证代码无状态部署，也就是任何一台服务器上的node代码复制到其他服务器，必须都能正常启动。无需做任何运维方面的处理（运维只提供上述node和pm2）。

2、运行服务器上只提供  node和pm2，其他node 模块不需要运维安装，也就是运维除了执行： npm install -g pm2，其他安装命令运维不执行。

3、在${项目目录}/bin,里面有三个运维脚本：start.sh、stop.sh、restart.sh 

4、所有对外提供http服务的，必须存在一个t-s.html，里面内容：${项目名}  is ok。保证通过：http://${域名}/t-s.html能访问到

5、代码业务日志：尽量输出到：${项目目录}/logs/下，主日志文件：${项目目录}/logs/stdout.log，pm2的日志，可以单独处理。

6、监控方式：需要给出来。运维只判断进程和http://${域名}/t-s.html

7、如果node项目代码里有静态资源，静态资源必须上线到cdn中。node本身只提供页面内容访问，不提供静态资源访问（另外：cdn有利于用户体验）

8、生产环境http端口上线，需要找运维申请


## 发布流程

一、代码必须放在公司统一的gitlab上。

二、发布过程：

拉取代码，build, 静态资源分离，同步预发

build过程：最好${项目目录}/bin下提供一个package.sh 脚本，也可以提供READMR.md文档，我根据文档写对应的脚本。

静态资源编译后，需要在dist/statics目录下。输出目录名：dist
